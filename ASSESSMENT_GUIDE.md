# Assessment Guide

## Порядок выставления оценки

1. Сначала проверить критические требования из `ASSIGNMENT.md`.
2. Затем выставить баллы по каждому разделу 100-балльной rubric.
3. Зафиксировать конкретное evidence для снятых баллов.
4. Добавить bonus только после выполнения обязательной части.
5. Дать студенту короткий письменный feedback: сильная сторона, основной риск и
   следующий шаг развития.

## Контрольные вопросы

- Почему RDS находится в private subnets?
- Чем readiness probe отличается от liveness probe?
- Как frontend находит backend внутри cluster?
- Почему GitHub OIDC безопаснее постоянных AWS access keys?
- Где хранится Terraform state и что предотвращает concurrent apply?
- Что произойдёт после удаления frontend Pod?
- Как выполнить rollback на предыдущий image?
- Какие resources продолжают стоить деньги после завершения демонстрации?

## Признаки поверхностного выполнения

- студент не может объяснить YAML/Terraform resource;
- production credentials находятся в `.env`, workflow или Git history;
- основные resources создавались вручную в Console;
- deployment работает только после ручных команд, отсутствующих в README;
- screenshots показаны вместо live-команд без объяснимой причины;
- публичный backend или database использованы для обхода networking.

```text

Bonus: __ / 15
Критические требования: выполнены / не выполнены

Основной технический риск:
Что улучшить первым:
Cleanup подтверждён: да / нет
```
